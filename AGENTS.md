# AGENTS.md

One codebase, several apps (since 10/2026): **stede** (bundle `de.letzgo.stede`, Ammerland, app shell `stede/`) and **Loog** (bundle `de.letzgo.loog`, Langeoog, app shell `loog/`, formerly its own repo, archived 10/2026 as `1letzgo/loog` on GitHub) are built from the same package; each region switches building blocks on or off. ## Brands & building blocks (10/2026)

Every app shell is a thin target in `stede.xcodeproj` (`stede`, `loog`; schemes of the same name, Loog's scheme carries `loog/Loog.storekit`) that sets `StedeBrand` in its Info.plist and calls `AppStartup.registerBackgroundTasks()` in `init` and `AppStartup.run()` on launch (StedeUI/Support/AppStartup.swift: purge, tenant refresh, place/file sync, warm-ups per building block). **`AppBrand`** (StedeCore/Support/AppBrand.swift) holds what is fixed per app: display name, `region` (`tenants.region`: `ammerland`, `langeoog`), default tenant, `choosesTenant` (municipality picker), URL scheme, colour palette prefix (`StedeX` / `LoogX` colorsets in StedeUI's Colors.xcassets, read by `StedeTheme`), `placesTitle` („Stadt“/„Insel“), `bikesInShopping`, privacy URL and `allowedFeatures` / `defaultFeatures`. **Building blocks** (`Feature`: weather, calendar, train, bus, waste, ferry, tides, air, groups, plus, politics; plus the place directories) come per tenant from `tenants.config.features` (`{"ferry": true, "places": ["gastro", …]}`, missing key = off, missing object = brand defaults); `Features.has(_:)` = tenant ∩ brand. ## Build & verify

- Layout since 09/2026: the Xcode project holds only the app shell (`stede/stedeApp.swift`, `Info.plist`, entitlements, `Assets.xcassets` with AppIcon + AccentColor). All code lives in the local Swift package `Packages/Stede` with two targets: **StedeCore** (Models, Services, Support/{IslandTime,LoadState,FlexibleDecoding}, `Resources/*.json` — pure Foundation, no UI, everything the UI needs is `public`) and **StedeUI** (Views, ViewModels, StedeTheme, InAppBrowser, `Resources/Colors.xcassets` with the `Stede*` colorsets; `ContentView` is the only public entry). Resources load via `Bundle.module`, colours via `Color("StedeX", bundle: .module)`. Add new files under the matching `Sources/<Target>/` folder (SwiftPM picks them up; the Xcode project file stays untouched except for the package reference). Language mode Swift 5 with approachable concurrency features; StedeUI has `.defaultIsolation(MainActor.self)`, StedeCore is nonisolated by default. No CI, no lint config. Verification = compile:
  ```
  xcodebuild -project stede.xcodeproj -scheme stede -destination 'generic/platform=iOS Simulator' build CODE_SIGNING_ALLOWED=NO
  ```
- Xcode 26.3; deployment targets 26.2 on iOS, macOS, and visionOS (`SUPPORTED_PLATFORMS` includes xros). Keep code multiplatform: guard iOS-only APIs (e.g. `BackgroundTasks`) with `#if os(iOS)`.

## Critical project settings

- **Filesystem-synchronized project**: the app folder `stede/` is synced; sources live in the package. Never edit `project.pbxproj` to add files (only `Info.plist` is excluded via membership exception; the package is referenced as `XCLocalSwiftPackageReference Packages/Stede` with product `StedeUI`).
- **Default MainActor isolation** (`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`): every type is MainActor-isolated unless marked `nonisolated`. Non-UI code (clients, models, support types) is explicitly declared `nonisolated` + `Sendable` — follow that convention or you'll hit Sendability errors.
- App Sandbox + hardened runtime are on; `stede.entitlements` already has network-client. `Info.plist` only sets `ITSAppUsesNonExemptEncryption`; no background task, no StoreKit (all features are free).

## Architecture

Flow: `Views/` → `@Observable` ViewModels (`ViewModels/TabViewModels.swift`) → `*Store` (caching, `Services/`) → `*Client` (`Services/APIClients.swift`, pure fetch+parse, `nonisolated`).

- **IslandTime** (`Support/IslandTime.swift`): ALL day boundaries, formatting, and timezone logic must go through it (Europe/Berlin, de_DE). Never use `Calendar.current` or default `DateFormatter` — the app shows island time regardless of device locale. Root locale is forced to `de_DE` in `stedeApp`.
- **DayCache\<T\>** (`Services/DayCache.swift`): per-day JSON disk cache in Application Support (`<name>/YYYY-MM-DD.json`). New day-cached content needs a cache name registered in `CacheMaintenance.dayCacheNames` or it never gets purged (7-day retention).
- ViewModels use cache-then-network: show cached data immediately, refresh in background, keep stale data on error (`.failed` only when nothing cached). `LoadState`/`AppError` in `Support/LoadState.swift`; German error messages via `AppError.errorDescription`.
- **Design system** (`Support/StedeTheme.swift` + asset catalog): Westerstede palette derived from westerstede.de (09/2026: city logo petrol #294754 and rhododendron red #E30613, site petrol #294753, Stadtgrün #37AB49, orange #FF8A00, site blue #2E6EA5, warm greys #F1EFEE), role names kept from the island app: `StedeTheme.sand/surface/harborRed/duneGreen/sunAmber/seaTeal/deep/heather/mudflat` (light+dark colorsets `Stede*`) — bar/deep/ink = petrol #294753 (bar #1F3640 and ink #9FC3D0 in dark mode), harborRed = logo red #E30613, duneGreen = Stadtgrün #37AB49, sunAmber = orange #FF8A00, seaTeal = site blue #2E6EA5 (accent: time pills, highlighted cards, action chips, Bus), heather = rhododendron magenta, mudflat = warm brown; sand/surface #F1EFEE/#FFFFFF (dark #121719/#1E2528); accent `StedeTheme.iconBlue` and `AccentColor` are petrol #294753 (#9FC3D0 dark). Android `C` in `ui/Theme.kt` has the same values. The app icon is a light rhododendron blossom (#BCC3C6) on petrol #1F3640. `StedeTheme.deep` stays dark in both modes (filled chips); for text and symbols in that tone use `StedeTheme.ink` (petrol / light petrol in dark mode). Cards via `.stedeCard(highlighted:fill:)` with inner padding `StedeTheme.cardPadding` (16), one-line list cards via `.stedeRowCard()` (`rowPadding` 12/16); every page and every sheet gets the petrol bar via `.stedeBar()`, sheet forms/lists via `.stedeSheetForm()` (sand background); text fields inside cards are `StedeTextField` (sand capsule). **Bahn** (`Models/TrainDeparture.swift`, `TrainClient`, `TrainStore` — an actor holding the last board for 60 s, no DayCache): the departure monitor `dbf.finalrewind.org/Westerstede-Ocholt.json?version=3` (DB IRIS, open source). It knows only „now“ and roughly the next two hours (`lookahead` is ignored), so `TrainViewModel` shows `.empty` for any day but today. bahn.de's own board API (`www.bahn.de/web/api/reiseloesung/abfahrten`) answers 403 to the app, and bahn.expert's `POST /api/orpc/iris/departures` (`{"json":{"evaNumber":"8004610","lookahead":600,"lookbehind":10}}`) would be the alternative with a longer horizon. Times come as „HH:mm“ and are placed on today (after-midnight rows on tomorrow); the client merges the double listing of ICs with Nahverkehrsfreigabe (`RE IC56` + `IC 2034` → one row) and sorts trains into `TrainDirection` Oldenburg/Leer by the route stops after Westerstede-Ocholt. `TrainView` (pushed from Start via `HomeDestination.train`) has the direction switch on top; `ContentView` owns the selected direction and persists it via `@AppStorage("train.direction")` (`TrainDirection` is `String`-backed). **Bus** (`Models/BusDeparture.swift`, `BusClient`, `BusStore`, `BusView`, `HomeDestination.bus`): the VBN HAFAS board `fahrplaner.vbn.de/bin/stboard.exe/dn?L=vs_java3` (XML `<Journey …/>` rows) per stop id and day — 120 rows per call, the client pages by time until the day is covered, keeps only `prod` `#Bus`, `delay="-"` means no realtime. `BusStop.all` comes from table `bus_stops` (09/2026: every VBN stop inside each municipality boundary — VBN `query.exe` locator grid, ids resolved via `ajax-getstop.exe` so saved selections stay valid, `sort_order` 0 = default stop; public read, service role writes; synced completely by `ContentSync.syncAll` / Android `Places.sync` into `content/bus-stops.json`), falling back to the `content_files` copy and, for Westerstede, a bundled list of 22 stops (ZOB first); the chosen stop lives in `@AppStorage("bus.stop")`, read independently by `BusView` and `HomeView` (not passed through `ContentView`, which would re-render the whole TabView on every change), picked only in Einstellungen via `BusStopSheet` (a `List` sheet; no `Menu`/`Picker`: their labels redraw late) — `BusView` shows it in the bar title („Bus – ZOB“); today's list hides departures that have already left. Start shows Bahn and Bus side by side under „Unterwegs“, then a compact „Abfuhr“ tile under „Zuhause“ (next collection of the chosen street). **Abfuhr** (`Models/WasteCalendar.swift`, `WasteClient`/`WasteStore` in `Services/WasteStore.swift`, `WasteView`, `HomeDestination.waste`, Start section „Zuhause“): the Ammerland waste calendar via appfuhr.de, which only offers PDF export — the client calls `api/makekal.php?uid=<32 hex>&str=<street>&strgr=<section|null>&astgr=<branch|null>&komp=false&vier=false&jahr=<yy>&max=999`, then `pdf/makepdf.php?uuid=…&str=…&jahr=…&sw=false`, downloads `pdf/tmp/<uid>.pdf`, reads it with PDFKit and `WastePDFParser` turns lines like „Freitag, 2.1. Restabfall“ into `WasteCollection`s (kinds Restabfall / Papier / Gelber Sack / Bioabfall / Ast- und Strauchwerk / Problemstoffe). Two collections on one day print the date only once: the second kind stands alone on the next line (often with month labels in between) and belongs to the last date — both parsers (iOS `WastePDFParser`, Android `Waste.parse`) handle it; the cache files carry a `v2-` prefix since that fix so old, incomplete years are re-fetched. Results are cached per street+section+year in `Application Support/waste/v2-<key>.json` (yearly data, never purged). The 548 Westerstede streets ship in `Resources/abfuhr-strassen.json` (from `api/json.php?tbl=str&ort=5`, 14 of them with `sections`/`branchSections` from `tbl=strgr`/`tbl=astgr`); the chosen street and sections live in `@AppStorage("waste.street"/"waste.section"/"waste.branchSection")`, plus the two options from the appfuhr website in `waste.noOrganic` (Eigenkompostierer, no Biotonne → `komp=true`) and `waste.fourWeekly` (Restabfall every 4 weeks → `vier=true`), toggles under Einstellungen → Zuhause, passed through `WasteSelection` (own cache key suffix `-nobio`/`-4w`) to `waste-calendar` (`komp`/`vier` query params, own server cache key) and the direct appfuhr fallback, wrapped by `WasteSettings` (StedeUI); street and sections are picked only in Einstellungen (`StreetSheet`), `WasteView` links to Einstellungen while nothing is chosen. Unofficial private service — re-check yearly, data is „Ende 2025“. **Kalender**: the city's event search `www.westerstede.de/regional/veranstaltungen/suche.html` (NOLIS-Manager, 15 hits per page, `p0` pages, `zeitauswahl=4` with `beginn_datum`/`ende_datum`), parsed by `EventHTMLParser` from the `terminanker_<id>` blocks (title, date/time incl. end time, Kurzbeschreibung, Veranstaltungsort, Veranstalter, Rubrik, series note, detail URL). Weather comes from Bright Sky for 53.256/7.927 (Westerstede). Weather `api.brightsky.dev`. Air quality was removed completely (09/2026) — no UBA station near enough. These return inconsistent types — use `FlexibleDecoding.swift` helpers and `JSONDecoder.api` for dates. `HTTPClient` sets a Safari User-Agent (some endpoints require it).
