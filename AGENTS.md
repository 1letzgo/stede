# AGENTS.md

SwiftUI app "Stede" (bundle `de.letzgo.stede`): town guide for Westerstede (Ammerland). Forked 09/2026 from the Langeoog app "Loog", Bahn (Westerstede-Ocholt), Kalender, Wetter, POIs and the offline map are Westerstede; only the air-quality station is still Langeoog. Ferry and tides were removed 09/2026. All user-facing strings and comments are **German**.

## Build & verify

- Layout since 09/2026: the Xcode project holds only the app shell (`stede/stedeApp.swift`, `Info.plist`, entitlements, `Assets.xcassets` with AppIcon + AccentColor). All code lives in the local Swift package `Packages/Stede` with two targets: **StedeCore** (Models, Services, Support/{IslandTime,LoadState,FlexibleDecoding}, `Resources/*.json` — pure Foundation, no UI, everything the UI needs is `public`) and **StedeUI** (Views, ViewModels, StedeTheme, InAppBrowser, `Resources/Colors.xcassets` with the `Stede*` colorsets; `ContentView` is the only public entry). Resources load via `Bundle.module`, colours via `Color("StedeX", bundle: .module)`. Add new files under the matching `Sources/<Target>/` folder (SwiftPM picks them up; the Xcode project file stays untouched except for the package reference). Language mode Swift 5 with approachable concurrency features; StedeUI has `.defaultIsolation(MainActor.self)`, StedeCore is nonisolated by default. No CI, no lint config. Verification = compile:
  ```
  xcodebuild -project stede.xcodeproj -scheme stede -destination 'generic/platform=iOS Simulator' build CODE_SIGNING_ALLOWED=NO
  ```
- Xcode 26.3; deployment targets 26.2 on iOS, macOS, and visionOS (`SUPPORTED_PLATFORMS` includes xros). Keep code multiplatform: guard iOS-only APIs (e.g. `BackgroundTasks`) with `#if os(iOS)`.

## Critical project settings

- **Filesystem-synchronized project**: the app folder `stede/` is synced; sources live in the package. Never edit `project.pbxproj` to add files (only `Info.plist` is excluded via membership exception; the package is referenced as `XCLocalSwiftPackageReference Packages/Stede` with product `StedeUI`).
- **Default MainActor isolation** (`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`): every type is MainActor-isolated unless marked `nonisolated`. Non-UI code (clients, models, support types) is explicitly declared `nonisolated` + `Sendable` — follow that convention or you'll hit Sendability errors.
- App Sandbox + hardened runtime are on; `stede.entitlements` already has network-client. `Info.plist` only sets `ITSAppUsesNonExemptEncryption`; no background task, no StoreKit (all features are free).

## Architecture

Flow: `Views/` → `@Observable` ViewModels (`ViewModels/TabViewModels.swift`) → `*Store` (caching, `Services/`) → `*Client` (`Services/APIClients.swift`, pure fetch+parse, `nonisolated`).

- **IslandTime** (`Support/IslandTime.swift`): ALL day boundaries, formatting, and timezone logic must go through it (Europe/Berlin, de_DE). Never use `Calendar.current` or default `DateFormatter` — the app shows island time regardless of device locale. Root locale is forced to `de_DE` in `stedeApp`.
- **DayCache\<T\>** (`Services/DayCache.swift`): per-day JSON disk cache in Application Support (`<name>/YYYY-MM-DD.json`). New day-cached content needs a cache name registered in `CacheMaintenance.dayCacheNames` or it never gets purged (7-day retention).
- ViewModels use cache-then-network: show cached data immediately, refresh in background, keep stale data on error (`.failed` only when nothing cached). `LoadState`/`AppError` in `Support/LoadState.swift`; German error messages via `AppError.errorDescription`.
- **Design system** (`Support/StedeTheme.swift` + asset catalog): Westerstede palette, role names kept from the island app: `StedeTheme.sand/surface/harborRed/duneGreen/sunAmber/seaTeal/heather/mudflat` (light+dark colorsets `Stede*`) — deep/bar/ink = logo petrol #284050, harborRed = logo red, duneGreen/sunAmber = westerstede.de green/yellow, heather = rhododendron magenta; accent `StedeTheme.iconBlue` is petrol-teal #1F6F80. `StedeTheme.deep` stays dark in both modes (bar, filled chips); for text and symbols in that tone use `StedeTheme.ink` (dark blue / light blue in dark mode). Cards via `.stedeCard(highlighted:fill:)`, icon tiles `StedeIconChip`, section headers `StedeSectionHeader` (system `.headline`, like Apple's own apps — no rounded design, no tracking). **Navigation** is fully native. `ContentView` is a `TabView(selection:)` with one `Tab` per `AppTab` (label = `AppTab.title`), each wrapping its screen in a `NavigationStack`. `TabScreen` (`Views/SharedViews.swift`) is the shared shell: it renders the content with `.refreshable` and drives the system navigation bar. The bar carries only the area name as the inline `title`. Day switching floats: `DayNavigator` is a Liquid Glass capsule (`glassEffect` in a `GlassEffectContainer`) overlaid just above the tab bar — chevron, the day („Heute" or „27. Aug. 2026") that opens `DatePickerSheet` (long-press jumps to today), chevron. `TabScreen` reserves `StedeTheme.SelectionRow.height` as bottom safe-area padding on every screen. `showsDateNavigator: false` (Start, Insel categories) omits the capsule. Wetter, Bahn and Bus are not tabs — Start pushes them with a `NavigationLink`, so they arrive with the system back button. Start tiles are `HomeTile` (tinted fill, 1 pt border in the area colour, large faded corner symbol, fixed `HomeTileMetrics.height` shared with the greeting card), grouped under `StedeSectionHeader` categories: „Unterwegs“ (Bahn, Bus), and „Stadt“: two large tiles side by side — „Entdecken“ and „Gastro“ (Restaurant, Café, Eiscafé, Imbiss, Bar in one filterable view) — then a row of four small tiles; formerly „Insel“ (built like Gastro: a large „Entdecken“ tile — Sehenswürdigkeiten plus the Freizeit & Sport facilities in one view — beside a row of Einkaufen (bakeries, drugstore and bike shops included), Spielplätze, Ausflüge and Gesundheit); „Externe Anbieter“/Strandkörbe were removed; within each section every tile has its own colour, and inside a category view every kind has its own colour and symbol too (pill, toggle, map pin — `IslandCatalog.color(for:)` / `symbol(for:)`); the greeting card on top doubles as the weather tile and pushes Wetter. Card action capsules use `StedeActionChip`. The tabs are Start and Kalender; no in-app purchase. Every screen spaces its cards by `StedeTheme.cardSpacing`. Bahn's direction switch and the Gastro/Fahrradverleih filter pills use `.stedeSelectionChip(isSelected:)` capsules at the top of the content, sized to their chips, starting 16 pt below the bar like the first card elsewhere and `cardSpacing` above the list. The bar itself is the logo's dark petrol green (`StedeTheme.bar`, colorset `StedeBar`, #284050 from the city logo): `.toolbarBackground(StedeTheme.bar, for: .navigationBar)` with `.toolbarBackgroundVisibility(.visible)` and `.toolbarColorScheme(.dark)`, so title, chevrons and the day button render white and the colour runs up into the status bar. Unlike the tab bar, which iOS 26 refuses to tint, the navigation bar takes the colour. The leading chevron group drops its glass capsule via `.sharedBackgroundVisibility(.hidden)`. Inside an `HStack` a `Divider()` renders vertically; use `Rectangle().fill(.separator).frame(height: 1)` for hairlines. Don't introduce ad-hoc colors; display numbers/titles use `.fontDesign(.rounded)`.

## Data sources (unofficial public APIs)

**All POI directories are offline OpenStreetMap data (09/2026).** `Resources/gastronomie.json`, `sehenswuerdigkeiten.json`, `gesundheit.json`, `freizeit.json` and `fahrradverleih.json` were generated from one Overpass query over the Westerstede municipality (`area[admin_level=8][name=Westerstede]`, amenity/shop/healthcare/tourism/historic/leisure tags) by a throw-away Python script: names, addresses, phone, website and `opening_hours` (day names translated, `seasonNote` „Laut OpenStreetMap, nicht bestätigt“) come straight from OSM, teasers are short generated German lines („Restaurant in Westerstede-Ocholt – italienische Küche.“) or hand-written for the notable places, coordinates are the OSM node/centroid; places without `addr:*` tags got their street via Nominatim reverse geocoding (59 of them, 09/2026). No photos ship (`GastroPlace.imageURL` stays nil), no `detailURL`. Same `GastroDirectory` schema as before (`source`, `fetchedAt`, `places[]`). Contents: **Gastro** 103 places in Restaurant / Café / Eiscafé / Imbiss / Bar / Bäckerei / Einkaufen / Drogerie (Einkaufen holds supermarkets, kiosks, florists, garden centres, bookshops, farm shops); **Gesundheit** 29 in Allgemeinmedizin / Facharzt / Zahnarzt / Apotheke / Klinik (Ammerland-Klinik, Bundeswehrkrankenhaus) / Therapie & Pflege / Tierarzt, the view adds 112/116117 and the Ammerland-Klinik emergency room; **Freizeit & Sport** 25 in Bad (Hössen Schwimmbad) / Sport / Spiel & Familie / Kultur (Stadtbücherei, museums, Freilichtbühne Howiek, Apothekervilla); **Sehenswürdigkeiten** 25 (St.-Petri-Kirche, Rhododendronpark Hobbie, Schloss Fikensolt, Draisinen-Bahnhof, Stadtpark, show gardens, churches — war memorials and minor artworks filtered out); **Fahrrad** (`IslandCatalog.bikeCategory`, was Fahrradverleih) 4 bike shops with `features` Verleih / Werkstatt / Verkauf / Fahrradladen — they have no tile of their own any more but are appended to the „Einkaufen“ view as kind „Fahrrad“. **Spielplätze** (`spielplaetze.json`, `GastroStore.playgrounds`, `IslandCatalog.playgroundsCategory`, tile in the Stadt row): the 34 municipal playgrounds scraped from westerstede.de/leben/kinder/kinder-spielplaetze (name, street, Besonderheit, Sauberkeit, Kinderrat grade as `seasonNote`), geocoded once via Nominatim; kinds Spielplatz / Skaterplatz. **Ausflüge** (`ausfluege.json`, 5, hand-written): Rhododendronpark Hobbie, Ammerland-Draisine, Park der Gärten, Zwischenahner Meer, Ammerländer Rhododendronroute with kinds Park / Draisine / Schifffahrt / Radtour. Symbols and colours per kind live in `IslandCatalog.symbol(for:)` / `color(for:)`. To refresh: re-run the Overpass query and the conversion (filters for memorials, school halls, shooting clubs), then re-check the hand-written teasers.

**Offline-Stadtkarte** (`Views/OfflineIslandMap.swift`, data `Resources/inselkarte.json`, ~2 MB): `LoogPlaceMap`'s UIKit map draws a blank `MKTileOverlay` plus our own overlays from an Overpass extract of bbox 53.19–53.28 N, 7.86–7.98 E (Kernstadt and Ocholt): `land` is the bbox rectangle, `polygons` settlement / green / wood / water, `buildings` (11k, tiny ones dropped), `lines` road / path / rail / stream — Douglas-Peucker simplified, 5-decimal coordinates. Layer keys `tidalflat`, `sand`, `dune`, `saltmarsh`, `groyne` are no longer present in the data but still tolerated by the renderer. Camera boundary centre 53.235/7.92, span 0.10×0.14; default region in `PlaceBrowsing` centres on the Marktplatz (53.257/7.927). Re-run the extract by hand when the town changes.

**Bahn** (`Models/TrainDeparture.swift`, `TrainClient`, `TrainStore` — an actor holding the last board for 60 s, no DayCache): the departure monitor `dbf.finalrewind.org/Westerstede-Ocholt.json?version=3` (DB IRIS, open source). It knows only „now“ and roughly the next two hours (`lookahead` is ignored), so `TrainViewModel` shows `.empty` for any day but today. bahn.de's own board API (`www.bahn.de/web/api/reiseloesung/abfahrten`) answers 403 to the app, and bahn.expert's `POST /api/orpc/iris/departures` (`{"json":{"evaNumber":"8004610","lookahead":600,"lookbehind":10}}`) would be the alternative with a longer horizon. Times come as „HH:mm“ and are placed on today (after-midnight rows on tomorrow); the client merges the double listing of ICs with Nahverkehrsfreigabe (`RE IC56` + `IC 2034` → one row) and sorts trains into `TrainDirection` Oldenburg/Leer by the route stops after Westerstede-Ocholt. `TrainView` (pushed from Start via `HomeDestination.train`) has the direction switch on top; `ContentView` owns the selected direction and persists it via `@AppStorage("train.direction")` (`TrainDirection` is `String`-backed). **Bus** (`Models/BusDeparture.swift`, `BusClient`, `BusStore`, `BusView`, `HomeDestination.bus`): the VBN HAFAS board `fahrplaner.vbn.de/bin/stboard.exe/dn?L=vs_java3` (XML `<Journey …/>` rows) per stop id and day — 120 rows per call, the client pages by time until the day is covered, keeps only `prod` `#Bus`, `delay="-"` means no realtime. `BusStop.all` is a curated list of 22 Westerstede stops (ids from the VBN `ajax-getstop.exe` search, ZOB first); the chosen stop lives in `@AppStorage("bus.stop")`, read independently by `BusView` and `HomeView` (not passed through `ContentView`, which would re-render the whole TabView on every change), picked via a full-width chip at the top of `BusView` that opens a `List` sheet (no `Menu`/`Picker`: their labels redraw late); today's list hides departures that have already left. Start shows Bahn and Bus side by side under „Unterwegs“. **Kalender**: the city's event search `www.westerstede.de/regional/veranstaltungen/suche.html` (NOLIS-Manager, 15 hits per page, `p0` pages, `zeitauswahl=4` with `beginn_datum`/`ende_datum`), parsed by `EventHTMLParser` from the `terminanker_<id>` blocks (title, date/time incl. end time, Kurzbeschreibung, Veranstaltungsort, Veranstalter, Rubrik, series note, detail URL). Weather comes from Bright Sky for 53.256/7.927 (Westerstede). Weather `api.brightsky.dev`; the UBA air-quality proxy still uses the Langeoog station. These return inconsistent types — use `FlexibleDecoding.swift` helpers and `JSONDecoder.api` for dates. `HTTPClient` sets a Safari User-Agent (some endpoints require it).
